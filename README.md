# Contact Lab — SQL Faker

My solution for Itransition Data Engineering task 6. The application generates fictional contacts for China and South Korea. All fake fields are generated by PostgreSQL stored procedures. Python renders the website, validates request arguments and reads the procedure results.

## Run locally

Python 3.10+ and PostgreSQL 15+ are required. With Docker Desktop, start the included PostgreSQL 17 instance:

```bash
docker compose up -d
```

Create the Python environment (Windows CMD):

```bat
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
copy .env.example .env
```

For the local Docker database, put this in `.env`:

```text
DATABASE_URL=postgresql://sqlfaker:local_demo_password@localhost:5433/sqlfaker
```

The password above belongs to the local demonstration container. Use your own hosted connection string for deployment. The `.env` file is ignored by Git and is loaded automatically.

Install the procedures and lookup data, then start the website:

```bat
python init_db.py
python app.py
```

Open http://127.0.0.1:5000. The documentation is at http://127.0.0.1:5000/docs. If PostgreSQL is already installed, create an empty database and use its connection string instead of Docker. A hosted PostgreSQL connection string also works locally.

On later launches, start the database if necessary, activate `.venv` and run `python app.py`. The installer is idempotent for the same dataset; run it again after updating the SQL procedures.

## Usage

Choose China (`zh-CN`) or South Korea (`ko-KR`), enter a nonnegative seed and generate a batch. Next and Previous navigate the dataset. Replay returns the same current contacts. The page URL retains the applied parameters.

Every contact has a native name with formatting variations, address, global coordinates, normally distributed height and weight, discrete eye color and blood group, varied phone format and email. Coordinates are uniform over the entire sphere and intentionally do not locate the postal address.

The UI supports 10, 25 or 50 contacts per batch. The SQL entry point accepts up to 1000, with one million addressable positions per locale/seed. Record identity depends on the absolute position, so changing the batch size does not change the contacts at the same positions.

## SQL library

The implementation is in `sql/02_procedures.sql`. The main call is:

```sql
CALL sqlfaker.generate_batch('zh-CN', 42, 0, 10, NULL);
```

This returns a JSONB array. There are separate procedures for uniform and normal draws, catalog loading, names, addresses, spherical coordinates, physical attributes, phones, email, individual contacts, batches, metadata and benchmarking.

No `random()`, `setseed()` or application-side fake-field generator is used. The state is local to each contact. A versioned MD5-derived starting state feeds a Park–Miller generator; normal samples use Box–Muller. Latitude is `degrees(asin(2u − 1))`, not a uniform angle. Details, signatures and examples are in [docs/procedures.md](docs/procedures.md) and on the website's `/docs` page.

Lookup values are stored in locale-keyed tables, rather than separate tables for each country. They are static data adapted from the MIT-licensed Python Faker and Faker JS projects and manually curated address components. The Faker packages are not application dependencies. See [data/SOURCES.md](data/SOURCES.md) and the included licenses.

Reproducibility depends on library version 1.0 and the stable lookup snapshot. The installer checks the dataset checksum before reusing an existing installation. A change to the lookup mapping needs a new dataset version rather than silently changing an existing one.

## Benchmark

The website includes a benchmark control for 1000 or 10000 contacts. For repeatable measurements:

```bat
python benchmark.py --count 10000 --batch-size 100 --runs 3
```

For a larger capacity run:

```bat
python benchmark.py --count 100000 --batch-size 100 --runs 3
```

The SQL procedure warms the batch path and measures full batch generation, JSON serialization and a rolling checksum using PostgreSQL's own clock. It excludes the network transfer of contact payloads and HTML rendering. The CLI records every run, the database version, its environment description and the median users/second in `benchmark_results.json`.

`docs/benchmark_results.json` contains the included measurement from PostgreSQL compiled to WebAssembly (PGlite), used for local verification in the build environment. It is an actual SQL measurement, not an estimate or a production Render/Neon measurement. Run the same benchmark against the deployed database and submit that result. CPU, load, database runtime and batch size affect the rate.

## Tests

```bat
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Tests connect to the PostgreSQL database configured in `.env` / `DATABASE_URL` and install the same schema and data if needed. Use a development database. They check replay, different seeds, pagination, the millionth position, native fields, phone shapes, lookup capacity, equal-area spherical bands, normal samples, SQL routine types, benchmark results and Flask routes. No generated contacts are stored in the database.

## Deploy

Create a PostgreSQL database and a Python Web Service from this repository. `render.yaml` contains the Render settings.

- Build: `pip install -r requirements.txt && python init_db.py`
- Start: `gunicorn app:app --workers 1 --threads 2 --bind 0.0.0.0:$PORT --timeout 300`
- Environment: `PYTHON_VERSION=3.11.11` and `DATABASE_URL` with the hosted PostgreSQL connection string.
- Health check: `/api/health`

Keep the database connection string in environment variables. It is never sent to the browser. Use SSL as required by the database provider. The database role needs permission to create the `sqlfaker` schema, tables and procedures for installation; runtime procedures use invoker permissions.

The deployed documentation URL is the application's URL followed by `/docs`. The benchmark can be run from a local computer against the same hosted database connection string, or through the website's benchmark control.

The optional Markov-chain text generator is not included.
